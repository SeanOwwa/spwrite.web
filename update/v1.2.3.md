A stability release focused on making SpwriteBot and the installers reliable
across Windows and Linux.

### Fixed

- **SpwriteBot could crash or error on Windows** while downloading its model or chatting if you closed a project mid-way. The assistant now safely ignores late updates once a project is closed.
- **Reopening a project during a model download no longer clashes.** Only one download per model runs at a time — reopen the panel and it simply joins the download in progress and shows its progress.
- **The Windows app now runs on a fresh PC.** It previously failed to start on computers without Microsoft's Visual C++ runtime (the "MSVCP140.dll not found" error). The needed runtime files now ship with the app.
- **The Windows version now installs properly.** It installs to your user folder and adds Desktop and Start menu shortcuts (after asking), instead of running loose from a copied folder — which could silently fail, especially on a OneDrive-synced Desktop.
- **Clearer model-download errors (seen on Linux).** A download that ends early, or a sign-in/proxy page answering instead of the real file, now gives a plain explanation of what went wrong — and a failed download is automatically retried once.
- **Installing on a Linux machine without a screen** (like a server over SSH) no longer fails trying to open a window. The installer notices there's no display, still builds the app, and can set up a lightweight remote desktop so you can connect and use it.
- **Fixed the Linux AI engine failing to build** during install by making sure the required build tools are installed.

### Known limitations

- On Windows inside a virtual machine, the app can still close while SpwriteBot generates a reply — the AI engine leans on CPU and graphics features a VM may not fully provide, and on having enough memory (8 GB recommended). Writing, editing, and keyword search are unaffected.
